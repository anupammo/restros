Foundations

The RestrOS design system

Two audiences with opposite needs. Operators want density, speed and zero ambiguity under pressure. Guests want warmth and a menu that reads like the restaurant. One token layer serves both by changing values, never structure.

OKLCH colour Fluid type Container queries Dark / light / system WCAG 2.2 AA Zero runtime dependencies

Principles

Speed is the feature

A cashier at 20:15 does not read; they recognise. Consistent position, consistent colour, ≥44px targets, and never a modal in the ordering path.

State is visible, not implied

An item with no price says “Needs price”. A late ticket turns red. We show the awkward state rather than hiding it behind an empty cell.

Brand belongs to the guest

Tenant colours drive the QR menu, bills and receipts. The operator console stays neutral so staff muscle memory transfers between outlets.

Colour never carries meaning alone

Every status pairs colour with a label or icon. Kitchens have bad screens and eight percent of men cannot separate red from green.

Colour

Authored in OKLCH so a ramp step is the same perceived step at every hue, and the dark theme is a lightness inversion rather than a second hand-tuned palette. Basil and Chilli are lifted straight from the Cafe Adda Khana menu card.

Semantic tokens

Components only ever consume these. Swapping a theme swaps this layer.

Three faces with distinct jobs. Bricolage Grotesque for display and numbers — it has the condensed energy of a hand-painted menu board. Inter for interface text. JetBrains Mono for order IDs, KOT numbers and anything a human reads aloud to another human.

Motion

Two curves. --ease-spring for anything that moves through space; --ease-out for anything that only fades or shifts colour. Everything collapses to 1ms under prefers-reduced-motion.

--dur-fast · 140msHover, colour, focus ring
--dur-base · 220msToggles, tabs, dropdowns, cards
--dur-slow · 380msDrawers, sidebars, sheets
--ease-spring cubic-bezier(.32,.72,0,1) — fast out, soft landing, no overshoot

Icons

One hand-built SVG sprite: 24px grid, 1.75 stroke, round caps. Referenced by <use href="sprite.svg#i-{name}"> so they inherit currentColor and cost a single cached request. No icon-font, no CDN, no layout shift.

Accessibility commitments

WCAG 2.2 AA is the floor, not the goal. A restaurant runs at speed in bad light.

ContrastBody text ≥ 4.5:1, large text and UI boundaries ≥ 3:1, in both themes.
FocusEvery interactive element has a visible :focus-visible ring with a 2px offset against the canvas.
Targets44×44 minimum on POS, KDS and guest surfaces; 30px permitted for dense desktop tables.
Motionprefers-reduced-motion removes transforms, shimmer and the live-dot ping.
SemanticsReal buttons, aria-pressed / aria-selected for toggles, aria-current="page" in nav, live regions for toasts.
KeyboardCtrl/⌘+K palette, F2 POS search, Esc closes every overlay, focus trapped in drawers.

Tokens live in assets/css/tokens.css. Nothing below that file hard-codes a colour.
